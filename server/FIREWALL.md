# 局域网访问与 Windows 防火墙——一次「手机连不上」的完整排查记录

> 背景：2026-09-24 为管理页加了手机扫码访问（服务端改监听 `0.0.0.0` + 标题二维码弹窗）。
> 重启后手机仍访问不了，本文记录排查过程与背后的原理，供以后遇到同类问题参考。

## 现象

- 电脑浏览器访问 `http://127.0.0.1:17321` 正常；
- 用本机局域网 IP 访问 `http://192.168.31.121:17321` 也正常；
- 手机（同一 WiFi）访问 `http://192.168.31.121:17321` 超时，连接根本到不了服务进程。

## 结论先行

两个独立问题叠加：

1. **Windows 防火墙拦截了手机的入站连接**（主因）——已有放行规则对不上当前环境（网络配置文件 + 程序路径双重错配）；
2. **二维码默认编码了虚拟网卡 IP**（次因）——`/api/lan` 按字典序把 WSL 虚拟网卡地址排在真实物理网卡前面，扫出来的地址手机天然不可达。

## 原理分层

### 1. 监听地址决定「谁能到门口」

TCP 服务 `listen` 时绑定的地址是第一道门：

| 绑定 | 含义 |
|------|------|
| `127.0.0.1` | 只收**本机回环**流量。同一台机器上 `curl 127.0.0.1` 能通；任何外部设备（包括手机）的包网卡层就不往这个 socket 送 |
| `0.0.0.0` | 收**所有本机网络接口**的流量：回环、WiFi 网卡、有线网卡、WSL/VPN 虚拟网卡……一视同仁 |

所以改 `0.0.0.0` 是必要条件——但不充分，因为过了网卡还有防火墙。

验证命令：

```cmd
netstat -ano | findstr :17321
:: 看到 0.0.0.0:17321 LISTENING 才说明绑对了
:: 若还是 127.0.0.1:17321，说明跑的是旧代码/没重启
```

### 2. Windows 防火墙：入站默认拒绝 + 规则三重匹配

Windows 防火墙（Windows Defender Firewall）对**入站**连接默认拒绝（出站默认放行），必须命中一条「允许」规则才能进。每条规则的匹配是**多维度同时成立**：

```
命中条件 = 方向(In/Out) × 协议(TCP/UDP) × 端口 × 程序路径 × 网络配置文件(Profile)
```

本次踩中的是后两个维度：

**① 网络配置文件（Network Profile）错配**

Windows 给每个网络打标：`公用(Public)` / `专用(Private)` / `域(Domain)`。首次连上一个 WiFi 时系统问「是否允许被发现」，选「否」就是 Public。防火墙规则按 Profile 生效——一条只勾了 Public 的规则，在 Private 网络里等于不存在。

本机情况：

```
Get-NetConnectionProfile → pure1_5G (WLAN) = Private   ← 当前 WiFi 是「专用」
已有 node.exe 规则       → Profiles: Public            ← 规则只管「公用」
```

Private 网络下这些规则全部不生效。

**② 程序路径错配**

规则按**可执行文件完整路径**匹配，不是按「node」这个名字。本机装过多套 Node 管理器：

```
规则里的路径   C:\...\fnm\node-versions\v24.14.0\...\node.exe
              C:\...\nvm\v22.19.0\node.exe
实际运行路径   C:\nvm4w\nodejs\node.exe                 ← 第三套，规则全落空
```

换 Node 版本/换版本管理器后，旧的程序规则静默失效——这是「以前明明可以」类问题的常见根源。

**为什么本机 `curl 192.168.31.121` 能通、手机不能？**
出站连接（本机 curl）默认放行，回包被当作「已建立连接的响应」也放行；而手机发起的是**入站**新连接，直接撞默认拒绝。同理 `netstat` 里全是本机 IP 的连接记录，看不到任何外部 IP——包在防火墙层就被丢了，服务进程一无所知。

**修复**（管理端执行，按端口放行而非按程序，免维护——换 node 版本不失效）：

```cmd
netsh advfirewall firewall add rule name="RouVideo Media Server 17321" ^
  dir=in action=allow protocol=TCP localport=17321 profile=private,public
```

### 3. 多块网卡 = 多个 IP，别信默认排序

`os.networkInterfaces()` 会列出**所有**接口：物理 WiFi、有线、WSL/Hyper-V 虚拟交换机（`172.x`）、VPN 隧道等。本机当时有：

```
172.22.224.1    ← WSL 虚拟网卡（只在物理机内部，手机路由不到）
192.168.31.121  ← 真实 WiFi 网卡（手机真正该扫的）
```

字典序 `172... < 192...`，二维码默认编码了虚拟网卡地址——就算防火墙放行，手机也永远连不上。
修复在服务端 `/api/lan` 排序：192.168/10 段（典型家用局域网）优先，172.16-31 段（虚拟网卡高发区）排后；弹窗另保留 IP 切换 chips 人工兜底。

> 更严谨的做法是按「拥有默认网关的接口」定位出口网卡，但 Node 标准库拿不到路由表；前缀启发式 + 人工切换对个人项目足够。

## 排查套路（可复用）

遇到「本机通、别的设备不通」，按链路自下而上逐层证伪：

1. **绑定对不对**：`netstat -ano | findstr :端口` —— `0.0.0.0` 还是 `127.0.0.1`？
2. **本机经局域网 IP 通不通**：`curl http://<本机局域网IP>:端口/...` —— 通 = 服务与绑定都没问题，问题在防火墙/网络层；不通 = 回到第 1 步。
3. **防火墙有没有对应规则**：`netsh advfirewall firewall show rule name=all verbose` 按程序名/端口找，重点核对 **Profiles 与 Program 路径**是否匹配当前网络与当前可执行文件。
4. **当前网络是什么 Profile**：`Get-NetConnectionProfile`。
5. **IP 给对没有**：多网卡机器确认客户端连的是物理网卡 IP，不是虚拟网卡/VPN 地址。
6. **包到底到没到**：`netstat` 看有没有外部 IP 的连接记录；一条都没有 = 防火墙/路由器 AP 隔离层丢弃（路由器开了「AP 隔离/客户端隔离」也会让手机摸不到电脑，本次未遇到）。

## 本次落点

- 防火墙规则 `RouVideo Media Server 17321`（TCP 17321 入站，Private+Public，不限程序）；
- `server/src/features/system/routes.ts` `/api/lan` IP 排序启发式；
- 设计文档 §3/§5 安全注记同步（监听 `0.0.0.0`、局域网来源写操作仍 403 = 手机端只读）。
