## 2. 总体结论

项目三组件边界清楚，文档完整度较高，服务端 feature 化、DTO 类型复用、测试基础和本地零运行时依赖等方向正确，不需要推倒重构。

当前主要风险集中在以下方面：

1. 服务端测试隔离不足，存在误写真实数据库和固定 D 盘目录的风险。
2. 服务监听局域网后，“只读”声明没有形成真正的写入安全边界。
3. raw 扫描的取消、局部失败和作用域语义可能造成误判消失或错误配对。
4. 头像、视频、封面等文件移动与 SQLite 写入缺少统一、可恢复的事务模型。
5. 扩展保存链路把 HLS 分段边界错误地当作 PES/AU 边界，收尾状态机也存在重复 rename 和过早删除完成文件的问题。
6. 扩展路由、offscreen 会话、跨标签页 OPFS 文件和下载账本均缺少统一的操作代次、锁与事件顺序。
7. 管理页存在请求乱序、对象引用导致播放器重建、busy 弹窗仍可关闭等异步一致性问题。

建议按“测试与 LAN 安全 → 扫描和文件一致性 → 扩展保存状态机 → 账本和数据库约束 → 前端竞态 → 构建与发布门禁”的顺序分批整改。

## 4. P0：优先修复

### 4.1 服务端测试没有完全隔离

**位置：**

- `server/src/test/setup.ts:1-2`
- `server/src/app.test.ts:414-423`
- `server/src/app.test.ts:614-628`

**问题：**

- 测试初始化使用 `process.env.ROU_MEDIA_DB ??= ':memory:'`。如果开发环境已经设置 `ROU_MEDIA_DB`，测试会直接使用该数据库。
- 多个测试执行无条件业务表清理。
- 集成测试会在固定的 `D:\archives\...` 路径创建并递归删除目录。

**影响：**

一旦外部环境变量指向生产库，或固定测试目录与用户目录重名，标准测试命令可能破坏真实数据；在无 D 盘或受限 CI 环境也无法稳定运行。

**建议：**

- 测试强制覆盖为独立内存库或随机临时数据库，检测到外部生产路径直接失败。
- 所有文件系统测试使用 `mkdtemp()` 创建唯一目录。
- 清理逻辑只允许操作带本次随机标记的路径。
- 增加“无 D 盘、只读仓库目录、生产环境变量已设置”三类隔离测试。

### 4.2 LAN“只读”没有形成真实写保护

**位置：**

- `server/src/app.ts:15-26`
- `server/src/app.ts:61-68`
- `server/src/features/studio/routes.ts:60-76`

**问题：**

- 服务监听 `0.0.0.0`。
- POST/PUT 仅在存在 `Origin` 且不匹配白名单时拒绝；没有 `Origin` 的请求直接放行。
- 所有 GET/HEAD 匿名开放，包括媒体内容、绝对路径、账本和日志。
- 服务端 Logo URL 抓取允许任意 HTTP/HTTPS 地址并自动跟随重定向。

**影响：**

同一局域网内任意 curl、脚本或非浏览器客户端都可调用归档、删除、账本修改、配置修改和 shutdown 等写接口。Logo URL 抓取还形成 SSRF 与无界响应内存风险。

**建议：**

优先选择以下一种方案：

1. 恢复只监听 `127.0.0.1`。
2. 写接口使用强随机 bearer token，LAN 读接口使用独立只读配对 token。
3. 如果必须同端口，至少不能把 `Origin` 或 `Host` 当认证；Origin 缺失必须拒绝。
4. URL 抓取默认禁用，或解析 DNS 并拒绝 loopback、私网、链路本地和每次重定向目标。

当前文档已经接受“LAN 匿名读媒体”，但匿名写并未真正被阻止，这是实现与安全声明不一致。

### 4.3 扫描取消或局部失败仍可能判定文件消失

**位置：**

- `server/src/features/raw/scanner.ts:187-214`
- `server/src/features/raw/scanner.ts:289-330`
- `server/src/features/raw/files.ts:443-450`

**问题：**

- `walkRoot()` 遇到取消时直接返回，但调用方仍会把当前作用域加入 `completed`。
- 子目录 `readdir`、文件 `stat`、抽样 hash 失败时静默跳过，调用方仍将作用域视为完整遍历。
- 只有一个盘或最后一个盘扫描中取消时，`st.canceled` 可能仍为 `false`。
- 移动配对查询只按 `volume/type` 筛选，没有使用扫描根边界。

**影响：**

拔盘、权限拒绝、坏文件和取消扫描后，尚未访问的现存文件可能被标记为 `pending_missing`；扫描根外同 hash 的归档行还可能参与错误配对，导致 raw 行身份、归档状态和事件记录错误。

**建议：**

- 为每个 `(volume, root, type)` 维护 `complete/partial/canceled` 状态。
- 只有完整遍历且未取消的作用域才能参与配对与消失判定。
- 文件“确实不存在”和“暂时无法读取”必须分开表达。
- 配对查询必须包含 root 路径边界。
- 增加末盘取消、权限拒绝、单文件 stat/hash 失败和根外同 hash 测试。

### 4.4 文件归档与数据库落库缺少可恢复事务

**位置：**

- `server/src/features/raw/files.ts:384-435`
- `server/src/features/video/routes.ts:84-121`
- `server/src/features/actress/routes.ts:119-133`

**问题：**

- 视频和封面分别移动，第二次失败时没有整体回滚。
- 文件移动完成后才写 `videos` 和关系表。
- 冲突预检使用 `fs.access()`，与实际 move 之间存在 TOCTOU。
- 跨盘回退使用可覆盖目标的 `copyFile()`。
- 头像固定命名为 `head.{ext}`；同扩展名替换会先覆盖旧头像，再因 `raw_files.path UNIQUE` 冲突回滚。

**影响：**

可能产生半归档文件、孤立路径、raw 行与磁盘分叉；同扩展名头像替换还可能造成旧头像内容不可恢复地丢失。

**建议：**

建立持久化归档 journal，例如：

```text
prepared → files_moved → db_committed → completed
```

同时增加源/目标路径锁、排他创建、跨盘临时文件与校验、启动时未完成操作恢复，以及覆盖前的引用检查。

### 4.5 HLS 分段边界被错误当作 PES/AU 边界

**位置：**

- `src/net/save-session.js:188-194`
- `src/hls/ts-remux.js:1117-1151`
- `src/hls/ts-remux.js:1336-1345`

**问题：**

每个 segment 结束后都会调用 `checkpoint()`；checkpoint 会强制完成 PES、NAL、AU 并清空 demux 状态。下一 segment 的 continuation PES 在 `pesAcc` 已清空后会被丢弃。

**影响：**

HLS 合法地跨分段携带 PES/NAL/AU 时，输出 MP4 可能丢帧、损坏或时间轴异常。

**建议：**

- checkpoint 必须保存跨边界 demux carry state。
- 或只在确认完整 PES/AU 边界时落盘检查点。
- 增加 PES、NAL、音频帧跨分段的真实 fixture。

### 4.6 扩展保存收尾状态机存在两个确定问题

**位置：**

- `src/net/save-session.js:225-278`
- `src/net/save-session.js:285-307`
- `src/net/fswriter.js:172-186`

**问题：**

- `#finishMp4/#finishTs()` 已执行一次 `moveTo()`，`#finishViaDownloads()` 又执行一次。
- 落盘回调返回后，在检查 `r.ok` 之前就删除完整 OPFS 文件和 sidecar。

**影响：**

- 重复 rename 可能在真实 Chrome OPFS 上导致正常下载失败。
- 下载目录空间不足或 `chrome.downloads` 中断时，完整视频会被删除，重试只能从第一段重新下载。

**建议：**

将保存过程拆为 `remuxed → renamed → downloading → complete/failed`，只有 `chrome.downloads` 成功确认后才清理 OPFS；失败时保留可重试的最终文件与 manifest。

## 5. P1：高优先级正确性问题

### 5.1 扩展路由、offscreen 会话和 OPFS 文件缺少统一并发控制

**位置：**

- `src/main.js:244-347`
- `src/offscreen.js:48-90`
- `src/net/save.js:85-120`
- `src/net/save-session.js:91-104`

**问题：**

- SPA 路由切换没有 operation generation，旧 `bootVideo()` 和下载回调可写入新页面状态。
- offscreen 每条消息直接启动异步 `handle()`，没有按 `saveId` 串行化。
- abort 可与正在执行的 OPFS chunk 写并发。
- `state.starting` 只在单标签页内防重；同一目标的多个标签页可同时删除、追加或恢复同一个 `.part`。

**建议：**

统一引入 `routeId + operationId + attemptId`，offscreen 使用 per-save 队列，扩展对 canonical target path 建立带 owner/过期时间的租约锁。

### 5.2 嗅探 URL 可能优先于页面权威地址

**位置：**

- `src/main.js:253-270`
- `src/page-hook.js:10-47`
- `src/net/sniffer.js:4-24`

**问题：**

候选顺序先使用所有嗅探 URL，再使用 `PageInfo.masterM3u8`；MAIN-world 嗅探集合不会随 SPA 路由清空，Performance Resource 还可能包含旧路由资源。

**影响：**

广告、推荐、多清晰度或 SPA 切换场景可能选错 playlist，并以当前页面文件名保存错误媒体。

**建议：**

页面数据地址优先；嗅探只作为 hint，并绑定 video id、请求时间和 route generation。

### 5.3 下载账本上报无顺序且无持久重放

**位置：**

- `src/main.js:132-184`
- `src/background.js:227-244`
- `server/src/features/ledger/downloads.ts:32-52`

**问题：**

`downloading/complete/failed/canceled` 全部 fire-and-forget；Service Worker 并发发送；服务端没有 attemptId、事件序号或终态保护，最后到达的请求直接覆盖状态。

**影响：**

`complete` 可能被迟到的 `downloading` 覆盖，账本长期卡在进行中；服务离线期间事件直接丢失。

**建议：**

- 每次尝试生成 `attemptId` 和单调 `sequence`。
- 扩展侧维护持久 outbox，并按 videoId 串行重放。
- 服务端使用幂等事件和显式状态机。

### 5.4 服务在线返回 false 时不会继续历史回退

**位置：**

- `src/background.js:150-155`
- `server/src/features/system/routes.ts:51-65`

**问题：**

本地服务只要返回结构合法的 `exists:false`，扩展就停止，不再查询 `chrome.downloads` 历史。

**影响：**

raw 索引尚未建立、文件从未进入 RawFiles、或账本上报曾丢失时，服务在线反而可能屏蔽历史层的有效证据，造成重复下载。

**建议：**

服务响应增加索引完整性和版本信息；服务命中 true 可短路，但 false 应与 legacy 结果合并，或只有能证明索引完整时才把 false 视为权威结论。

### 5.5 数据库关系完整性不足

**位置：**

- `server/src/lib/db.ts:11-18`
- `server/src/features/video/videos.ts:21-24`
- `server/src/features/video/routes.ts:47-64`
- `server/src/features/video/routes.ts:109-121`

**问题：**

- 未启用 `PRAGMA foreign_keys = ON`。
- 关系表没有外键。
- 删除标签、片商、演员、国家没有统一级联或限制策略。
- 归档接口只验证第一位演员；其他演员、标签、片商、国家 ID 可形成孤儿关系。

**建议：**

先执行一次孤儿数据审计，再启用外键并明确 `CASCADE/RESTRICT`；所有文件操作前完成全量引用校验。

### 5.6 管理页存在可复现的异步竞态

**位置：**

- `server-web/src/features/Video/ArchiveDialog.tsx:63-80`
- `server-web/src/features/Video/ArchiveDialog.tsx:104-116`
- `server-web/src/features/Video/ArchiveDialog.tsx:172-178`
- `server-web/src/components/VideoPlayer/index.tsx:26-30`
- `server-web/src/components/RatingInput.tsx:15-22`
- `server-web/src/features/Video/Video.tsx:117-123`
- `server-web/src/features/Actress/Actress.tsx:73-87`

**问题：**

- 归档表单每次 render 都创建新的播放源对象，播放器 effect 依赖整个 `item`，导致视频反复销毁重建。
- 评分滑块每个 `onChange` 都立即写库，没有 debounce、串行化或响应版本检查。
- 封面自动匹配只请求前 50 条，服务端又按 `last_seen` 排序；迟到响应可覆盖用户手动选择或清空。
- busy 弹窗仍允许 Esc、遮罩和取消按钮关闭，后端文件操作继续执行。

**建议：**

播放器 effect 依赖稳定的原始字段；评分使用独立端点和串行 outbox；封面查询提供服务端精确匹配并实现 latest-request-wins；busy 期间禁止关闭。

### 5.7 服务关闭与 HLS 资源缺少统一生命周期

**位置：**

- `server/src/features/system/routes.ts:106-119`
- `server/src/lib/hls-core.ts:237-241`
- `server/src/lib/hls-core.ts:265-297`
- `server/src/lib/hls-core.ts:399-429`
- `server/src/lib/hls-core.ts:451-477`

**问题：**

- shutdown 直接 `process.exit()`，不排空扫描、归档和活动 HTTP 请求。
- HLS session、ffmpeg 进程、等待队列和临时缓存没有全局上限。
- 客户端断开后 waiter 仍可能保留到超时。
- 启动时缓存清理未等待完成。

**建议：**

增加维护模式、活动操作计数、优雅关闭、ffmpeg 终止等待，以及 session/进程/缓存配额和请求取消。

## 6. P2：工程与维护改进

### 6.1 统一质量门与 CI

当前 pre-commit 只执行扩展根检查：`tools/hooks/pre-commit:1-3`，仓库未发现 CI workflow。建议：

- 根目录增加 `check:all`，串行执行三组件检查。
- CI 使用 `npm ci` 后执行 `check:all`。
- 管理页构建后验证 `server/public` 与源码构建结果一致。
- 不依赖只存在于当前机器的 `core.hooksPath`。

### 6.2 跨组件版本握手

`/api/ping` 当前没有服务版本、API 版本、schema 版本或 build ID：`server/src/features/system/routes.ts:38-48`。建议建立统一 release/compatibility 信息，前端和扩展遇到不兼容时明确报错，而不是把旧服务错误伪装为空列表。

### 6.3 扩展 ID 与 native host 配置可移植性

扩展 ID、Origin 白名单和 native host manifest 多处硬编码。仓库移动、换机器或扩展 ID 改变后，native messaging 和写接口可能失效。建议集中配置并在安装时检测实际扩展 ID。

### 6.4 数据库迁移与备份

当前采用启动时直接 DDL、`ALTER TABLE` 捕获所有异常和 `PRAGMA user_version=1` 的局部迁移。建议：

- 使用单调 schema version 和逐版本事务迁移。
- 只吞掉明确的 duplicate-column 错误。
- 破坏性迁移前自动生成一致性备份。
- WAL 模式使用 SQLite backup/checkpoint，不能只复制主 `media.db`。

### 6.5 API 客户端与页面状态模型

`server-web/src/lib/api.ts:37-43` 不支持调用方 AbortSignal、超时和受控重试；多个页面使用裸 fetch 并吞掉错误。建议建立统一的 `idle/loading/success/error` 状态模型，列表请求 latest-request-wins，mutation 成功后局部更新再后台 revalidate。

### 6.6 管理页性能

本次测得 `server/public/assets/app.js` 约 1,010,436 bytes。所有 tab、hls.js、PhotoSwipe 和二维码逻辑均由 `server-web/src/App.tsx:3-17` 首屏同步导入。建议按 tab 动态导入，并延迟加载播放器和图片查看器依赖。

### 6.7 可访问性与故障恢复

- `server-web/src/main.tsx:6-9` 没有根级或页面级 Error Boundary。
- 移动端关闭的侧边栏仍保留在 DOM 和键盘 Tab 顺序中：`server-web/src/components/Layout/index.tsx:88-120`。
- `server-web/src/features/Video/VideoCard.tsx:51-57` 的封面点击可能被全尺寸播放按钮覆盖。

建议补充错误边界、焦点管理、真实坐标点击测试和键盘可访问路径。

### 6.8 文档与版本元数据

审查基线中的根 `README.md` 只有标题；部分 DESIGN 已出现行为漂移；根 `package-lock.json` 仍记录 1.7.0，而 `package.json`/`manifest.json` 已是 1.14.0。建议补充统一入口、版本一致性和文档契约检查。

## 7. 已接受取舍与条件性风险

以下项目在本次 review 中不作为“未发现限制的确定缺陷”处理，但仍应保留明确边界：

1. **同名 stem/文件名误匹配**：账本和 raw 层存在同名误报可能，文档已记录并提供强制下载逃生门。
2. **MV3 跨域请求边界**：`src/net/http.js:4-7` 假设 host permissions 可满足 CDN CORS/鉴权，需要用真实无 ACAO、重定向和鉴权场景验证。
3. **MP4 32 位索引限制**：`stco` 等字段不支持超过 4 GiB 的文件；应明确产品限制或升级到 `co64`。
4. **HLS 格式覆盖**：fMP4、Byte Range 和非 188 字节 TS 当前未完整支持，应显式检测并拒绝，避免静默生成错误文件。
5. **LAN 匿名读媒体**：属于已经记录的个人项目取舍，但其隐私和资源消耗风险仍真实存在。
